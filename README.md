# 中文去 AI 味写作技能

**natural-writing-zh** 用于中文新写与改写，重点处理套话、刻意抒情、生硬衔接、过度解释，以及脱离上下文的角色台词。覆盖文章、PPT 文案、策划案、小说、游戏台词和游戏内文案。

去 AI 味需要检查一段话为什么出现在这里、读者此时需要什么信息。只换掉几个高频词，常常会留下原来的问题；一味口语化，又容易把正式文章改得过于随意。本技能按文体处理这些差别，保留有用的解释和原本合适的表达。

## 可以改善哪些问题

| 文体 | 常见的 AI 味 | 处理重点 |
|---|---|---|
| 文章 | 客套、空泛收尾、突然省掉主语，段落各自通顺却接不上 | 按读者理解顺序组织，保留必要过渡，保持专业的书面表达 |
| PPT 文案 | 封面塞满细节；删完又只剩口号；用设问假装有重点 | 区分主副标题，用时间轴、流程和对照组织实质内容 |
| 策划案 | 反复写“以下为建议”“确认后落实”，没有真正展开方案 | 直接列安排、分工与节点，关键缺项集中注明 |
| 小说 | 环境、回忆、台词拼接生硬，人物突然理解或突然感动 | 检查视角、动作与认知变化，让铺垫和转折在场景中成立 |
| 游戏台词 | 人人说金句、互相解释已知设定、回应像工作登记 | 按身份、关系和当前目的说话，允许用动作承接回应 |
| 游戏内文案 | 按钮过度文学化，任务和操作含义不清 | 先说明状态、操作及后果，再匹配游戏气质 |

小说和台词优先沿用已有作品风格。没有指定风格时，默认偏二次元的幻想冒险表达；角色关系与行动比堆口头禅更重要。本技能负责文案，实际制作 PPT、Word 文档或实现游戏还需相应工具。

## 安装与第一次使用

这是供 AI 助手读取的技能文件，不是双击运行的软件，也不会训练或更换模型。下面以本地 Codex 为例；日常写作不需要安装 Python。

**最省事的方式：把下面这段发给能访问本机文件的 Codex。**

```text
请使用 skill-installer，从 https://github.com/momowangOUO/natural-writing-zh
安装仓库根目录的 natural-writing-zh 技能。
先检查是否已安装；若已存在，核对版本与差异后更新，不要安装重复副本。
保留其他技能和已有配置。完成后读取 SKILL.md，告诉我安装位置及是否能调用。
```

也可以[下载安装包](https://github.com/momowangOUO/natural-writing-zh/releases/latest)，解压后手动放入技能目录。[新手指南](docs/installation.md)包含 Windows、macOS 的具体步骤、正确目录示意、安装检查与常见问题。

安装后，在写作请求中明确指定技能：

```text
使用 $natural-writing-zh 改写下面的文章，去除 AI 味。
读者是第一次了解这个项目的玩家。保留事实和必要解释，保持专业，
不要一律改成口语；原本自然的句子可以保留。

原文：……
```

新写也可以直接调用，例如“使用 natural-writing-zh，根据这些资料写一份试玩执行案”。可提供读者、用途、原稿或事实材料；小说与台词再补充角色关系和前后剧情。自动调用取决于任务匹配，重要任务可以明确点名。调用机制见 [OpenAI 技能说明](https://learn.chatgpt.com/docs/build-skills)。

## 游戏台词：先写纯文本，再接入项目

直接在代码里边填字符串边编对白，容易顾得上结构却顾不上整段对话。本技能默认先完成可连贯阅读的独立文本稿。

1. 读取项目的角色、设定、场景和显示限制。
2. 在 Markdown 或文本文件中写稿，把编号、触发条件与玩家看到的文字分开。
3. 连贯检查整段对话或操作流程，确定文本版本。
4. 按编号填入项目已有的字符串、配置或本地化资源。
5. 从项目读回，核对文字、变量、换行与分支。放不下时先改稿，再同步。

```text
使用 $natural-writing-zh，为现有场景补写对话并接入项目。
先读角色和前后剧情，独立保存纯文本稿，检查通过后再填入现有资源。
保留变量和分支，接入后读回核对。
```

只要求文案时交付文本；要求实现时继续完成接入。不会另建一套通用游戏文本系统。格式与可选 Python 核对工具见[接入说明](references/game-handoff.md)。

## 效果与验证范围

目前完成的是规则、示例与反馈校准。**去 AI 味的效果通过具体修改来判断，不提供 AI 检测率或“完全像真人”的承诺。**

| 已做的检查 | 范围与结果 |
|---|---|
| 六类文体各两题，共十二题 | 在同一对话中生成、检查并调整，包含新写、改写和保留原文 |
| 小说、台词、界面文案各一次复写 | 用于观察重复套路；仍受同一对话上下文影响 |
| 文本核对与接入工具测试 | 14 项通过，8 条示例文字接入后读回一致 |
| 技能结构与发布检查 | 元数据、文件引用、安装文件和下载包已检查 |

跨对话、其他模型的稳定性尚未验证；技术测试不能证明文风自然，也不替代实际游戏画面和 PPT 排版检查。查看[题目](tests/writing-cases.md)、[输出](tests/writing-outputs.md)与[详细记录](tests/RESULTS.md)可以了解每项检查的依据。

## 反馈与维护

发现生硬表达时，可以在 [Issues](https://github.com/momowangOUO/natural-writing-zh/issues) 提交文体、用途、必要上下文、原句，以及具体别扭的位置。若有偏好的改法也可附上；请先去掉私人材料。反馈会用于调整对应规则和示例，避免只为一个句子增加禁词。

本次仓库说明使用 natural-writing-zh 的文章规则与校准参考编写。规则和示例为重新编写，未复制旧 humanizer-zh 的规则正文或示例库。公开阅读资料的观察见[来源说明](references/source-observations.md)。
