# 游戏内文案

先看显示位置、玩家当前状态、可以采取的行动和已有术语。读取项目中的界面、任务状态与文本约束；没有依据时不编造奖励、概率、冷却、机制或按钮功能。

| 类型 | 写作重点 |
|---|---|
| 按钮、菜单、选项 | 准确标明操作或选择；与实际行为一致；同一动作名称保持一致 |
| 任务目标 | 让玩家知道当前要做什么，必要时说明对象或地点；不提前泄露后续阶段 |
| 错误、状态提示 | 说明当前问题和可用的下一步；不以客套话替代解决信息 |
| 教程 | 在相关操作出现时给出必要信息，按真实输入方式写按键或手柄提示 |
| 物品说明 | 区分功能信息与风味描述，关键效果可直接找到 |
| 世界观文本 | 保留作品声音与适度含蓄，区别于任务指令或系统反馈 |

“不要提前回答所有问题”不等于删掉操作后果、消耗、覆盖存档等会改变玩家决定的信息。必要提示在选择前出现，低优先级说明可由详情或帮助承接。

界面用词以准确、熟悉为先。不把普通操作重新命名成难懂的世界观词，不在失败提示中训斥玩家，不让按钮和报错都像角色在发表宣言。

保留项目的变量、标记、单位与术语。字数限制先从项目确认；需要压缩时保留动作、对象和关键后果。接入后检查真实显示，不能靠删除关键内容解决溢出。

涉及项目写入时，按 [纯文本接入](game-handoff.md) 完成独立文本稿、检查和读回核对。
